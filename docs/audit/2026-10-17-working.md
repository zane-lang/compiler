F01 [High] The generic-instantiation limit mistakes finite usage for infinite recursion
lib/tst/check/instances.ml:13-15; lib/tst/check/instances.ml:119-131
instance_counts is keyed only by declaration id and counts every distinct argument set across the entire build. The 65th set is rejected with a claim that the verb's calls to itself never reach a fixed set. No recursion or call ancestry is inspected. A non-recursive identity-like generic called with 65 distinct types/numeric arguments hits this limit.
Evidence: Confirmed by source trace; compiler reproduction unavailable.

F02 [Medium] Target selection accepts layouts that the rest of the compiler cannot represent
lib/codegen/build.ml:25-42; lib/cgt/nodes.ml:39-61; lib/codegen/frames.ml:12-17; runtime/zane_internal.h:175-188
target_machine accepts any triple registered by LLVM, including 32-bit targets. CGT fixes pointer size/alignment at 8, handles at 24, payloads at offset 8, scope records at 224 and task headers at 96. No target-width/ABI validation appears before emitting target-specific LLVM types. Object/IR output can use inconsistent offsets; runtime compilation for a 32-bit target fails its fixed-offset static assertions.
Evidence: Confirmed by source trace; 32-bit object emission not executed.

F03 [Low] Diagnostic carets use code-point counts rather than terminal cell widths
lib/diagnostic/render.ml:12-44
visual_col_of_idx and expand_tabs count every UTF-8 leading byte as one column. Combining marks occupy zero cells and wide CJK/emoji commonly occupy two. Diagnostics after such text (including string literals before an error) point at the wrong displayed column.
Evidence: Confirmed by algorithm inspection.

F04 [Low] The diagnostic underline gutter stops aligning at double-digit line numbers
lib/diagnostic/render.ml:84-93
The source row uses `%d | ` but the caret row always starts `  | `. At line 10 and beyond the caret row begins one or more cells to the left of the source text.
Evidence: Confirmed by format strings.

F05 [Medium] LLVM compilation resources have no owned lifecycle in the driver API
lib/codegen/emit.ml:1076-1080; lib/codegen/build.ml:31-41; lib/codegen/build.ml:85-99; lib/driver/driver.ml:121-133
Each emit creates a fresh LLVM context and module; emit and prepare each create a target machine. Driver.ir/executable/object_file consume the module but never dispose it or its context, and target machines have no matching explicit disposal. The only dispose_module in lib/codegen disposes a tiny temporary attribute module. Repeated compilation in one process retains module/context allocations, including failed builds.
Evidence: Confirmed absence of context/module disposal in all source; native memory growth not measured.

Verification checkpoint: all nine tests/runtime/*.c compiled with GCC -std=c11 -Wall -Wextra -Werror -O2 -pthread. Every test exited 0 and matched its golden stdout with ZANE_CHECK=0 and ZANE_CHECK=1 (18 runs).

F06 [Medium] Package-alias validation treats uppercase Unicode identifiers as lowercase
lib/tst/model/env.ml:101-106; lib/tst/passes/collect.ml:163-185; lib/cst/lexer.ml:77-78
The lexer classifies Unicode uppercase names as UIDENT, but Env.is_upper examines only the first UTF-8 byte with Char.uppercase_ascii/lowercase_ascii. A package alias beginning with Ü or Ω evades the initial-case rejection that an ASCII uppercase alias triggers. It is recorded as a package qualifier even though later grammar positions distinguish uppercase type names from lowercase package qualifiers.
Evidence: Confirmed by lexer/helper/call-site trace; compiler execution unavailable.

F07 [High] An aggregate-returning main is exported with an incompatible runtime entry signature
lib/tst/passes/verb_signatures.ml:793-807; lib/cgt/program.ml:346-387; lib/codegen/emit.ml:1112-1130; runtime/zane.h:50; runtime/main.c:71
Semantics explicitly permits any main return type. When there are no non-lambda package constants, lowering marks the user's main itself as the entry; codegen renames that function zane_main without changing its return type. The C runtime declares and calls void zane_main(void). Large aggregate returns need return storage that this caller never supplies. The void startup wrapper is emitted only when constants exist, so unrelated constants change which entry ABI is used.
Evidence: Source trace plus reduced LLVM IR/C reproducer: LLVM 20.1 emitted define [10 x i64] @zane_main(); linking it to extern void zane_main(void) and calling it exited -11. Pinned LLVM 19/full Zane compilation unavailable.

F08 [High] The large-aggregate guard misses function parameters
lib/codegen/big_moves.ml:119-137; lib/codegen/emit.ml:1060-1066
Big_moves' final limit check examines only instruction result types and explicitly exempts allocas. Function parameters and signatures are not examined. Emit stores every non-void parameter into an alloca; a store's result is void, so an exported function taking [65536 x i64] can reach native code generation without the promised diagnostic even if its parameter is otherwise unused.
Evidence: Source trace plus reduced IR with a [65536 x i64] parameter stored into an alloca: LLVM 20.1 object emission exited -11. Exact compiler/LLVM 19 execution unavailable.

F09 [High] Memoized output replay bypasses the compile-time evaluator's resource budget
lib/optimize/eval.ml:41-44; lib/optimize/eval.ml:574-594; lib/optimize/eval.ml:602-604; lib/optimize/materialize.ml:10-11
A cached call replays its entire output list with List.rev_append without spending steps or charging its size. Print adds an output without charging text/list storage, and memo entries have no output-size or total-cache cap. A recursive function that calls its previous level twice and prints once at its base accumulates exponentially many output-list nodes while memoized computation takes only linearly many calls. The materialization cap is applied after evaluation and cannot bound these allocations.
Evidence: Confirmed by budget and memo call paths; intentionally no out-of-memory stress run.

F10 [Medium] Package-constant cycle detection cannot detect a cycle spanning contexts
runtime/value.c:105-130; lib/cgt/program.ml:100-104
Constant_begin detects only state == this context's id+1. If two contexts begin constants A and B respectively, then each reads the other's unfinished constant, both wait on the condition variable forever. No context can reach constant_end to wake the other. A constant initializer can invoke spawned work, so pre-main initialization does not exclude this state.
Evidence: Reproduced against actual runtime/value.c: two pthread contexts begin their own states, synchronize on a barrier, then begin the other's state; process timed out after 3 seconds.

F11 [Medium] Drained one-MiB chunks are cached forever with no bound or release path
runtime/arena.c:183-203; runtime/arena.c:235-256; runtime/snapshot.c:130-146
zane_unmap returns every ordinary ZANE_CHUNK mapping to context->spare instead of freeing it. Idle contexts transfer all spares to a global pool, and allocation consumes spares, but no code trims either cache. A temporary scope's high-water ordinary-chunk footprint remains resident for the rest of the process even after every allocation dies. This is retained free capacity, not an ownership leak.
Evidence: Actual-runtime RSS probe executed; measurements recorded in verification checkpoint.

F12 [Medium] Negative parser tests accept internal compiler errors and signal crashes as correct rejection
tests/parser/syntax_test.py:34-36
assert_rejects checks only returncode != 0. A compiler exit 3 (internal error), abort, or SIGSEGV passes the same assertion as the expected source rejection exit 1, hiding robustness regressions across the rejection cases.
Evidence: Confirmed directly from the test assertion.

F13 [High] Large array lengths truncate at the LLVM boundary and overflow CGT byte arithmetic
lib/tst/passes/type_decls.ml:427-436; lib/tst/model/ty.ml:40; lib/cgt/nodes.ml:44-61; lib/codegen/emit.ml:49; lib/codegen/frames.ml:27-40
Number arguments are OCaml ints with no maximum tied to layout. CGT retains n and computes stride*n and frame additions without checked arithmetic. On a 64-bit OCaml runtime, an I64 array with n=2^60 wraps its computed byte size to 0. Separately, Llvm.array_type in the pinned LLVM 19 binding calls LLVMArrayType with Int_val(Count); that C API takes an unsigned 32-bit count, so n=2^32 produces a zero-length LLVM array while CGT offsets/bounds still carry the original n.
Evidence: Source trace and pinned LLVM 19.1.7 binding inspection; complete oversized-array Zane build not executed.

F14 [High] A small incomplete multi-scrutinee match allocates its entire exponential case space
lib/tst/check/check.ml:1084-1102
Exhaustiveness checking materializes the complete Cartesian product as combos, then the complete missing list, before retaining only three examples for the diagnostic. With 30 two-case scrutinees and a single arm this attempts 2^30 combinations from a source program linear in 30. There is no budget or early diagnostic bound on this semantic path.
Evidence: Confirmed by the Cartesian-product construction; no intentionally exhaustive allocation run.

F15 [Medium] Array ownership metadata expands one entry per element before backend size checks
lib/cgt/type_layout.ml:158-174; lib/codegen/walks.ml:552-555; lib/codegen/big_moves.ml:44-46
For an array whose element owns any block, positions builds List.init n and concatenates each element's positions. This work occurs during lowering, before Big_moves can reject an oversized aggregate, and walks later emit code per position. An array of strings/recursive owned values therefore consumes linear compiler memory and generated walk code in its declared length, even when source describes it in a few tokens.
Evidence: Confirmed source path; no large allocation run.

F16 [High] Expanding generic recursive types evade the boxing traversal's cycle detector
lib/cgt/type_layout.ml:68-86; lib/tst/passes/type_decls.ml:267-295; lib/tst/passes/type_decls.ml:852-867
boxed follows inline owning members with a seen list of fully instantiated Ty.t values. A variant such as Grow<T> with a terminating case and a recursive Grow<Array<T,2>> case generates Grow<T>, Grow<Array<T,2>>, Grow<Array<Array<T,2>,2>>, ...; neither the holder equality nor the full-type seen test ever matches. Semantic wrong-kind checks stop by declaration id and do not reject this expansion; the distinct-cycle pass covers only Distinct definitions. Asking for this type's layout can recurse without end until a compiler stack overflow.
Evidence: Confirmed by substitution/traversal trace; exact source reproduction not run.

F17 [Medium] Failed exclusive creation during object rewriting deletes the file that caused the collision
bin/zanec/zanec.ml:358-374
run_rewrite chooses a temporary name, opens it with Open_excl, and unconditionally Sys.remove's that name in the Sys_error handler. If exclusive creation itself fails because the name already exists, the compiler never owned that file but deletes it anyway. This contradicts the function's output-preservation guarantee.
Evidence: Confirmed from exclusive-open and unconditional cleanup control flow.

F18 [Medium] The --stamp option accepts malformed stamps that the other stamp-taking paths reject
bin/zanec/zanec.ml:125-132; bin/zanec/zanec.ml:212-220; lib/driver/driver.ml:26-40; lib/cgt/program.ml:233-245
package_id and --rewrite/--remap validate stamps with Rewrite.is_stamp. --stamp PATH=STAMP checks only the path and that the value is nonempty, then Driver applies it unchanged. Lowering later infers whether a package is stamped from the presence of %, so --stamp geometry=garbage can change the package id while being treated as unstamped by linkage classification. A malformed identity is accepted rather than a usage/build diagnostic.
Evidence: Confirmed by CLI-to-linkage trace.

F19 [Medium] Ambiguity-search timeouts accept NaN and infinity
tools/ambiguity/profiles.py:66-94; tools/ambiguity/engine/config.ml:190-194; tools/ambiguity/engine/search.ml:388
parse_duration checks only seconds < 0 after conversion. Numeric TOML nan/inf and sufficiently large digit strings pass. Config.settings likewise checks only value < 0 for --timeout, whereas it explicitly checks finiteness for max_frontier_ratio. A non-finite timeout reaches deadline arithmetic and no longer represents the requested finite search bound.
Evidence: Python reproduction: parse_duration(float('nan')), parse_duration(float('inf')) and parse_duration('9'*400) returned non-finite values without error.

F20 [Low] Source excerpts and diagnostic paths emit terminal controls unchanged
lib/diagnostic/render.ml:84-98; lib/diagnostic/render.ml:106-111
The renderer copies the source line and filename directly into terminal output; expand_tabs changes tabs only. A literal or path containing ESC/OSC/CSI controls is interpreted by the terminal instead of being displayed as source text. This can alter or erase the diagnostic and has effects beyond its visible characters.
Evidence: Confirmed raw-output path; no control sequences were executed in the user terminal.
